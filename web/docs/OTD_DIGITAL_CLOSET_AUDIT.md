### A. Current architecture

1. **Routes & Entry Points**
   - [App.tsx](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/App.tsx#L34-L86) mounts [`StudioLayout`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/App.tsx#L34-L86) -> [`AppStudio`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/AppStudio.tsx) for `/closet` and `/closet/add`, guarded by [`StudioRouteGuard`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/auth/StudioRouteGuard.tsx#L10-L160) (`status === 'authenticated' || status === 'guest'`).
   - Public landing route `/` mounts [`WardrobeStudio`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/WardrobeStudio.tsx#L9-L221) reading the same [`useCloset`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/ClosetContext.tsx#L687-L693) context; clicking its upload CTA navigates to `/closet/add`.
2. **State & Persistence Layer (Currently 100% Browser-Local)**
   - [`ClosetProvider`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/ClosetContext.tsx#L313-L685) seeds from `localStorage` (`otd_closet_items`) or 17 hardcoded items ([`INITIAL_CLOSET`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/ClosetContext.tsx#L282-L309), `t1..a2`) and performs synchronous void CRUD (`addClosetItem`, `updateClosetItem`, `deleteClosetItem`, `archiveClosetItem`, `restoreClosetItem`).
   - [`AuthContext`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/AuthContext.tsx#L24-L90) exposes `isAuthenticated`, `isGuest`, `canMakeProtectedRequests`, and user identity, but [`ClosetContext`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/ClosetContext.tsx#L313-L433) never reads auth state or scopes items by user. [`clearPrivateUserCaches`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/utils/authStorage.ts#L89-L116) intentionally preserves `otd_closet_items` on logout.
3. **Closet UI & Intake Utilities**
   - **Grid, filter, inspection, delete:** [`AppStudio`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/AppStudio.tsx#L2915-L3246) renders Active/Archived tabs, search, formality filter, sort, 5 category pills, empty states, inspection modal ([lines 3897–4046](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/AppStudio.tsx#L3897-L4046)), and delete/archive dialog ([lines 4048–4109](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/AppStudio.tsx#L4048-L4109)).

   - **Editing & dead code:** [`EditPieceModal`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/EditPieceModal.tsx#L596-L612) simulates a `450ms` save timeout and updates local state. [`AddPieceModal`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/components/AddPieceModal.tsx#L48-L250) is unused legacy code (not imported anywhere).
4. **Prepared-but-Unwired HTTP & WS7 Contract Layer**

### H. Risks and unverified areas

- **No runtime/E2E verification performed:** This audit was strictly read-only source inspection; live browser rendering, Vite `/api` proxy calls, real Express + MongoDB + GridFS responses, Multer multipart boundaries, and CORS/helmet image headers were **not executed**.
- **Silent metadata loss risk:** Until Vasant confirms `subType`, `fit`, `formality`, `pattern`, `secondaryColor`, and `isArchived`, authenticated users saving rich metadata in `ClosetUploadView`/`EditPieceModal` will lose those exact attributes upon reload and fall back to [`wardrobe.adapter.ts`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/adapters/wardrobe.adapter.ts#L150-L189) defaults (`'Regular'`, inferred formality).
- **Bearer-token image rendering complexity:** Because [`apiClient`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/services/api/apiClient.ts#L251-L256) attaches `Authorization: Bearer <token>` in memory rather than cookie auth on API routes, standard `<img src="/api/wardrobe/:id/image">` tags will fail `401` unless Vasant supports cookie/signed image URLs or the frontend fetches blobs via `apiClient` and revokes object URLs without leaking memory.
- **Account-switching cache leakage:** Because [`clearPrivateUserCaches`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/utils/authStorage.ts#L89-L116) spares `otd_closet_items` and [`ClosetProvider`](file:///c:/Users/pc/Desktop/OTD-Balaji/web/src/context/ClosetContext.tsx#L313) wraps the whole app above route changes, logging out of Account A and into Guest or Account B will leak in-memory closet state unless `ClosetContext` resets/rehydrates on `AuthContext` transitions.
- **Client memory/outfit breakage at scale:** Fetching all pages when a user has >100 items can cause multiple sequential requests; deleting a wardrobe item on backend leaves existing `Outfit` documents pointing to deleted IDs ([`outfits.service.ts`](file:///C:/Users/pc/Desktop/OTD-backend/AI-FASHION-OTD/src/modules/outfits/outfits.service.ts#L48-L61)).
